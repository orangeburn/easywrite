
# EasyWrite · 创作与叙事角度 Skill

## 路由入口（v0.3）——按任务目标选择工具，不按方法选题

**仅在作者要求找角度、创作或修改时进入本模块。** 找角度需要作者已结束本轮观点输出；已有角度、大纲或正文时，从本次要求的阶段继续，不重新要求完成观点池或选择角度。单纯检查材料由 [Review](../review/WORKFLOW.md) 处理；观点自由讨论不自动启动创作。

**找角度阶段的职责：把一批原始观点映射到可能的叙事探索路径，而不是预测点击率、评出“最优方法”或替作者做决定。** 从全部观点发现可独立展开的候选角度；同一个角度可以用多种方法探索，也可以不属于既有五类。方法只提示观察和提问方式，不提供点击效果保证。

候选探索入口：
- 已存在的群体情绪或争议 + 作者可辩护判断 → [情绪裁决](./methods/verdict.md)。
- 作者观点可能迫使特定读者修正既有理解 → [认知反转](./methods/reversal.md)。
- 可验证的异常结果 + 重要的解释缺口 → [异常解谜](./methods/mystery.md)。
- 观点中出现成本、收益、风险或决定权关系，可从不同当事人视角展开 → [利益揭示](./methods/interest.md)。
- 原始观点已有鲜明反常场景，或选定角度需要具象化表达 → [荒诞现场](./methods/absurdity.md)；注意真实现场与象征场景的区别。

**两层判断分开**：①事实与逻辑层：核验事件、公众说法、受众基础和作者论据，排除虚构或明显不成立的切口；②创作探索层：讨论哪种切口更易识别、更能表达作者观点及其局限。这些只是设计判断，不是经实验证实的点击率预测。没有可靠数据时，不给选题打点击分、概率、优先级，也不默认推荐唯一“最佳”。

默认最多展示三个**实质不同**的候选角度，分别说明所依据的作者原话、采用的方法、现实证据、主要不确定性及点击前可能产生的疑问；由作者选择。作者主动要求推荐时，允许基于其明确目标和可核验条件作**有条件的建议**，必须说明依据，不声称能预测传播效果。

**方法状态与证据等级**：五类为本项目的创作框架，不是学术界验证过的一组标准方法。情绪裁决法已有操作规则 v0.2；认知反转法 v0.3、异常解谜法 v0.1、利益揭示法 v0.2、荒诞现场法 v0.1 均已具备可执行规则。各法主用途不同，不代表已验证为五套独立点击机制。相关心理学研究或历史案例可能为单一机制提供旁证，**不得据此宣称整套方法已被验证**。


## 用途与调用边界

这是 Thinkit Lab 微信公众号的统一创作 Skill。负责从作者对一个话题自由输出的大量观点中探索可能具有点击前吸引力的**叙事切入角度**，再指导文章逻辑、大纲、标题与封面设计。适用于“帮我找角度”“从这些观点里选题”“重排大纲”“设计标题封面”“用裁决法”等请求。**统一入口负责调用边界与路由；各方法的具体执行规则位于 `methods/`，参考依据位于 `references/`。**

主目标：探索能够在读者尚未读正文时，通过标题、封面及已知语境形成点击理由的表达方式；不能把这项创作目标误写为已经能够预测或优化点击率的因果模型。阅读完成、共鸣、转发和商业转化是后续阶段，不得拿来代替点击判断。文章仍须以事实和论证兑现标题承诺。

**入口承接**：沿用统一入口确认的动作、材料、范围和作者决定。只有找角度时才执行下方完整探索流程；明确要求写大纲、正文、改局部或设计标题封面时，直接进入相应阶段。作者自由表达属于前置输入，不自动变成创作任务。

从观点找角度的执行顺序：**接收原始观点池 → 发现候选切入角度 → 用合适的方法探索（可多种或不套分类）→ 按成立前提联网查证与反证 → 呈现可选角度和局限 → 作者选择 → 筛选观点和重排逻辑 → 按需完成大纲、正文、标题封面 → 点击前检查。**

需要探索角度时，不在作者选择前排整篇逻辑或写全文；作者已明确角度或已有稿件只要求局部修改时，不再增加选角度环节。不得因为文章后续价值而忽略读者为何会点开。

## 0. 调用入口：读取作者已经输出完的观点池

调用时从既有聊天、作者自述、事件、争论、比喻、推测、反例及必要的 Notion 记录获取观点池。作者在 Skill 启动前已完成自由表达，材料可以不连贯、互相矛盾；要保留原始措辞，而不是先加工成一篇文章。

- 作者尚在输出观点：**不调用本 Skill**；按普通讨论回应，不自动截断作者表达，不抢先筛选角度。
- 作者结束观点输出并要求“找角度/选题”：启动本 Skill，直接扫描**全部**已给观点和原句，而非此前助手整理好的二次概括。提取候选对象、行为、情绪、旧有认知、反常结果、成本错位和具象场景。
- 必需材料足够时直接做；材料不足时指出**阻碍判断的唯一关键缺口**，不发宽泛问卷。
- 若用户已指定切入角度，则从该角度往后执行，不重复角度筛选。

## 1. 发现角度：内部分析与原始观点扫描

此阶段先用模型作**候选生成与逻辑分析**，不是用模型臆测今日舆论。

具体操作：

1. 遍历作者每个独立判断，寻找可被普通读者辨认的对象：品牌、产品、事件、行业概念、职场行为、制度规则、人物处境。抽象词（“时代”“商业逻辑”“人性”）必须落到具体行为才算切口。
2. 寻找明确可对抗的既有说法：谁声称什么、谁为某件事辩解、什么观念被默认正确；也寻找不需要两派对战的集体厌恶或挫败。
3. 寻找能独立成故事的“一个具体问题”：一次断裂、一次会议、一项KPI、一段甲乙方关系。避免一篇文章批判整个行业却没有一个可理解的动作。
4. 对不同切法各写一句“这篇文章选择从哪里进入，最终想证明什么”。这一步不写标题集，不排文章顺序。
5. 检查是否是同一个切口换了三个形容词。只有对象、要挑战的认识或故事因果不同，才算独立候选。

内部候选数量一般3—5个，公开呈现最多3个。优先保留作者有鲜明原始观点且有事实依据可查的候选。

## 2. 验证候选角度：研究其真正依赖的事实

**工具分工**：模型用于发现可能的切口、逻辑冲突和反例；互联网检索用于核对具体事实、当前公共讨论、目标读者是否存在相应认知或情绪。搜不到足够证据时报告不确定性；不把模型直觉、单个评论区或作者的假设写成公共事实。验证工作按候选所需进行，不对每个方法机械执行同一套“舆论争点”搜索。

1. **事实基础**：查原始事件、当事方资料、政策、论文、测试、数据、时间与后续澄清；优先一手来源。查证事实时同时检查替代解释和反例。
2. **方法特定前提**：裁决法查争议或既有群体情绪是否真的存在；反转法核实目标读者既有认知及新解释的依据；解谜法确认异常是真实而非误读；利益法追踪真实的利益、成本、责任分配；现场法还原场景并区分真实事实与文学化隐喻。
3. **目标读者与可识别性**：说明是哪个读者群体，以及对象、共识、情绪或具体处境在他们之中是否可识别。行业内熟悉不等于公众熟悉；若缺乏代表性的样本，不推断“主流”“全网”“大家都”。
4. **证据状态**：逐项区分「已查实的事实」「有依据的解释/推断」「尚无可靠证据」。优先记录会改变创作判断的反证和适用边界，避免只寻找支持材料。未经证实的动机不写成事实。
5. **是否适合继续探索**：事实基础不成立时淘汰；受众认知度不确定、传播效果不确定时保留为假设，并明确提示，不能因此虚构确定性。无法访问来源时直接说明。

涉当前事件按事实发生的日期和来源查找近期资料；长期共识或积怨允许使用更长时段的资料。阅读、转发、评论等数据不能自动推算点击率，也不能用文章发表后的情绪推断发表前就存在群体情绪。

旧文与历史覆盖：涉及作者曾经写过什么、发表时间或既有表达时，优先查询 Notion「Blog数据库」，只认 state=Published 且 type=Post，并读取相关正文全文；草稿或观点库按实际用途分别查询，不能只靠记忆。


## 3. 探索方法：按需加载，而不是强制分类

五种方法是不同性质的**创作工具**，不是相互排斥、同时为选题打分的五条点击规律。选择工具先看**作者当前要求完成的工作**，再看输入材料，而非先让所有方法参与选题。一个方法可跨阶段使用，不把下表当成绝对分类：

| 方法 | 主要适用工作 | 结果检查时关注 |
| --- | --- | --- |
| 情绪裁决 | 从既有态度中形成叙事立场；选角度后的标题与封面表达 | 对象能否识别、态度是否预先存在、判断能否兑现 |
| 认知反转 | 发现作者观点与读者已有理解的落差；表述差异 | 认知差是否真实且有实质修正 |
| 异常解谜 | 从反常结果发现解释型故事入口；安排解释承诺 | 异常是否真实、原因是否兑现 |
| 利益揭示 | 切换关系中不同当事人的位置；发现此前遗漏的角度 | 关系是否清楚、动机与收益是否偷换 |
| 荒诞现场 | 已有场景时发现入口；**更常用于选角度后的开头、叙事、标题封面** | 矛盾是否可感、事实与艺术隐喻是否分清 |

- **找选题／角度**：只用能从作者观点池中产生实质不同切口的方法；不因某个方法适合审查就强迫它生成选题。
- **作者已选角度**：不重新路由选题；可以按需使用裁决、现场、反转等方法增强叙事与标题封面表达。
- **要求检查结果**：拿已经生成的角度、开头或标题封面，调用能发现具体问题的方法及相关 Reference；反馈表达和事实边界问题，不借此替作者重新决定选题，也不冒充发布前商业审查框架。
- **一般交流／观点仍在输出**：不自动启动 Creation。

同一候选可采用两种方法，也可不属于既有五类；方法之间没有固定优先级。

- [情绪裁决法](./methods/verdict.md)：从熟悉对象与既有态度形成可辩护的裁决，亦可用于标题封面表达（v0.2）。
- [认知反转法](./methods/reversal.md)：从作者原始观点反向寻找其可能修正的目标读者既有理解，核验前提和表达风险（探索流程 v0.3）。
- [异常解谜法](./methods/mystery.md)：从可核实的反常结果寻找有价值的解释问题，检查解释是否可兑现（探索流程 v0.1）。
- [利益揭示法](./methods/interest.md)：从不同当事人的成本、收益、风险与决定权位置发现故事切口；事实查证作为输出边界检查（视角探索 v0.2）。
- [荒诞现场法](./methods/absurdity.md)：从具体行为或象征场景显出冲突，主要服务于叙事及标题封面的具象化（v0.1）。

找角度时，只有能从原始观点生成**实质不同切口**的方法才需要使用；表达或检查阶段的方法无需参与候选竞争。不能为了填满方法列表强行生成角度，**不得按未经验证的模型推测给方法或角度排点击率名次**。

**按任务读取 Reference，包括结果检查**：先读取本入口与实际用到的 `methods/`。当需要解释或修订方法，**或检查候选角度、标题封面、文章方案的输出是否有与相关研究或案例相冲突的推断**时，读取对应 `references/`。例如，若输出声称「认知冲突必然提升点击」，可查认知反转的研究证据，识别过度外推；但无关的参考文件、历史快照不必加载。Reference 用来辅助核对方法适用边界、证据局限与案例差异，**不能替代针对本次选题的事实、受众认知和舆情核验，也不能直接决定选题**。详情见 [references/README.md](./references/README.md)。


## 4. 候选角度的呈现与选择

从作者原始观点而非助手的二次归纳出发，最多呈现三个实质不同的候选角度。每个角度只需说清：

- **来源与切口**：对应作者的哪条原始观点？选择从哪个具体对象、行为或矛盾切入？
- **探索方法与读者关联**：采用什么方法帮助展开？哪个具体处境中的读者可能关心？
- **可验证依据**：哪些事实或既有认知已获得支持？哪些只是推测？
- **点击前的表达假设**：读者仅看到标题和封面可能产生什么疑问或态度？此项不等于已证明点击有效。
- **最重要的反证与风险**：是否存在认知基础薄弱、事实冲突、表达歧义等问题？

不默认选出一个“最佳”角度。若作者要求建议，可根据明确的创作目标、证据充分程度及可识别性解释倾向，但要承认真实点击结果无法事先确定。**作者确认角度后**才筛选观点、组织论证、撰写文章和设计标题封面。


## 5. 选定角度之后，才整理观点、逻辑与大纲

此时回到完整原始观点池，逐条判断：哪些是必须使用的事实、哪些提供关键解释、哪些反驳或限定结论、哪些属于另一个故事应删去或留作新选题。

为该角度形成一条主因果链：“具体处境/事件 → 被挑战的解释 → 关键事实 → 为什么造成这种结果 → 反例与适用边界 → 最终判断”。据此重排素材和设计大纲，不按用户发言先后组织内容。

同时回答原有写作总纲：“文章代表哪一个具体处境中的人、他正经历什么、最后替他说清什么话”。但**不让这三问反过来强迫作者选择未经验证的所谓高点击角度**。

尚在观点探索时不输出整篇初稿；只有作者要求正文时写正文。

## 6. 标题与封面：同一故事角度的双重表达

- 标题目标：尽可能快地让读者识别对象和矛盾，并提供认同、反驳、意外或好奇的点击理由。裁决式标题可采用事实裁决、行业模式裁决、趋势裁决、群体不满裁决；其他类型允许以异常、反转或成本作为入口。句式不是越极端越好，预测不得写成已发生事实。
- 封面目标：帮助认出对象/发生的事，或以视觉隐喻表达文章核心机制。优先找一件有辨识度的具体物体及一个可被看见的动作，不只是重复标题文字。既可以补足省略的主语，也可以通过既有谚语/象征引发联想。
- 同时要求标题与封面时，形成2—4组**标题+封面配对创意**，说明每组在点击前传递的同一个角度；只要求其中一项时不强制配对交付。选择哪一组由作者决定。
- 微信公众号以移动端小缩略图展示，检验主题是否可认出、元素是否过细或过多；特定画风（例如黑白、聚光灯）属于作者近期实验，不得当成因果公式或强制模板。
- 事件正在成为热点时可以使用依赖热点语境的短标题；当事件关注度下降、读者难识别时，标题或封面必须补足对象。

## 7. 发布前只检查“点击前”

让助手暂时当作完全没读过正文的读者，只看到标题与封面（以及真实的发布语境）：

1. 我认得这是在说谁/什么吗？
2. 我看到的是冲突、异常、裁决，还是一个陌生的空泛概念？
3. 为什么我会想“凭什么”“怎么会这样”“终于有人说了”？
4. 标题有没有过度承诺、偷换对象或暗示一个未经证实的事实？
5. 缩略图还能看懂关键物体和动作吗？

不符合则先改切入角度或标题封面，不用增加正文价值来辩护。微信当前缺少作者可执行的正式随机A/B分流，不把A/B测试当成默认步骤。若用户提供真实曝光、打开、推荐来源及展示方式，做观察性复盘；评论量、转发量不是标题点击率。

## 8. 源案例：校准而非套模板

- 《断了就是断了》：尊界踏板断裂已成为当时讨论焦点；标题省略对象、直接作事实裁决；封面是一根**断裂的巧克力棒**，靠“断了”的动作与热点语境发生联想。评论区的激烈争论不直接证明标题点击率。
- 《中国式FDE注定失败》：FDE是行业目标受众熟悉的讨论对象，“中国式”“注定失败”下趋势/模式裁决；封面是**从天而降的巨锤砸向一大排钉子**，指向“手里拿着锤子，看什么都是钉子”，隐喻预先有AI方案、然后为方案找问题，不是简单画一个“失败”。
- 《开会浪费生命》：对形式主义会议、职场政治表演的集体厌恶提供裁决切口，不必预先存在势均力敌的两派；文章论证需聚焦无效会议，不能把所有会议都未经限定地推为无用。

样本展示的是可供验证的创作因果假设，不能从三篇反推出普遍成立的点击率规律。

## 9. 输出契约、失败回退与存储

**探索观点阶段（Skill 外）**：作者自由讨论时不调用本 Skill；仅回应当下的观点问题，不擅自定主题。

**要求找角度阶段**：扫描原始观点，按方法探索并核验候选，呈现不超过3个不同角度及证据、反证、未知条件；不默认推荐唯一最佳，不提前写大纲。用户要求意见时提供有条件的建议，不假装预测点击率。

**确认角度后**：按本次请求输出观点取舍、因果链、大纲或正文，不重复索取角度确认；只要求大纲时不扩写全文。

**局部修改**：读取指定部分及必要上下文，保留已确认的主线与固定表达；只修改授权范围，不因进入 Creation 重跑选题或另写全文。修改完成即结束，不自动进入完整 Review。

**标题与封面**：同时要求两者时输出联动创意方案；只要求标题或封面时只交付对应部分，可检查与另一方的匹配，不自动生成另一方。需要正式生成图片时才执行图片制作。

**方法的成立条件缺失**：在当前任务阶段不适用就不使用；事实证据不足时说明关键缺口或将候选降为假设，不为套方法制造共识、敌人、悬念或荒诞现场。

**作者已提供足够事实**：保留作者陈述作为输入，不为了展示严谨而重复质疑；需要对外发布的重要客观事实才做必要的外部核验，并明确区分作者输入和检索证据。

**资料管理**：本模块以 `creation/WORKFLOW.md` 为内部入口，方法细则位于 `creation/methods/`，历史 Notion 文档仅存于迁移快照；单篇文章和观点另存用户指定的数据库。GitHub 为正式维护源，不把快照当最新规则。
