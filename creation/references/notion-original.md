## 路由入口（v0.1）

**调用门槛：作者已经输出完本轮观点池，并明确要求选题、寻找切入角度或调用本 Skill，才启动路由。** 观点输出和讨论本身发生在 Skill 之外，不是本 Skill 的第0步；不能在作者尚在表达时自动触发路由、归纳和选题。输入是调用时已积累的全部原始观点。若作者已经指定角度，则从相应后续阶段执行，不再路由。

方法路由以**候选叙事角度**为单位，不对整篇话题先贴一个方法标签。先从观点中识别具体对象、矛盾与可能成立的故事切口，再核对各候选成立条件。允许同一个话题出现采用不同方法的多个候选；选定角度之后才重排原始观点和设计大纲。

候选入口：既有群体情绪与可辩护判决 → 情绪裁决；**作者某个观点可能迫使目标读者修正既有理解** → 认知反转（先识别其挑战的默认认识、预期或通行解释，再核验证据及反转力度）；已发生的反常结果存在重要解释缺口 → 异常解谜；可追踪的成本、收益或权责错位 → 利益揭示；一个真实具体场景自身足够荒诞 → 荒诞现场。

先用模型从全部观点中生成候选，再针对成立前提联网核验。不能把模型印象当作公共情绪或主流认知证据。多个方法均成立时，优先比较目标读者的点击前识别度、故事冲突清晰度、证据充足度和具体切口；最多提供三个不同角度，推荐一个，作者最终决定。无有效候选时说明缺少的关键证据，不硬套方法。

**模块状态**：情绪裁决法已具备初版因果链和执行流程；认知反转、异常解谜、利益揭示、荒诞现场四法仅登记路由触发条件，均为“待逐步完善”。后续在本 Skill 中逐一补齐各方法的因果机制、证据需求、步骤、标题与封面策略及失效边界。不另建方法文档。

## 用途与调用边界

这是 Thinkit Lab 微信公众号的统一创作 Skill。负责将作者对一个话题自由倾倒的大量观点，转化为具有点击前吸引力的**叙事切入角度**，再指导文章逻辑、大纲、标题与封面设计。适用于“帮我找角度”“从这些观点里选题”“重排大纲”“设计标题封面”“用裁决法”等请求。**所有切入方法写在这同一份 Skill 中，不为每种方法另建文档。**

主目标：在读者尚未读正文时，凭微信信息流中可见的标题、封面及已知语境，形成点击理由。阅读完成、共鸣、转发和商业转化是后续阶段，不得拿来代替点击判断。文章仍须以事实和论证兑现标题承诺。

**Skill 调用时机：观点输出结束、作者要求进行选题或角度设计。** 作者自由表达属于前置输入阶段，**不属于 Skill 的内部步骤**。

Skill 内部执行顺序：**接收既有观点池 → 从原始观点中寻找候选切入角度并路由 → 按成立前提联网查证 → 推荐角度、由作者确定 → 筛选观点和重排逻辑 → 设计大纲与正文 → 标题封面联动 → 点击前检查。**

不得在角度确定前为整篇材料排逻辑、写大纲、强制归类所有观点；更不得因为文章后续价值而忽略读者为何会点开。

## 0. 调用入口：读取作者已经输出完的观点池

调用时从既有聊天、作者自述、事件、争论、比喻、推测、反例及必要的 Notion 记录获取观点池。作者在 Skill 启动前已完成自由表达，材料可以不连贯、互相矛盾；要保留原始措辞，而不是先加工成一篇文章。

- 作者尚在输出观点：**不调用本 Skill**；按普通讨论回应，不自动截断作者表达，不抢先筛选角度。
- 作者结束观点输出并要求“找角度/选题”：启动本 Skill，直接扫描**全部**已给观点和原句，而非此前助手整理好的二次概括。提取候选对象、行为、情绪、旧有认知、反常结果、成本错位和具象场景。
- 必需材料足够时直接做；材料不足时指出**阻碍判断的唯一关键缺口**，不发宽泛问卷。
- 若用户已指定切入角度，则从该角度往后执行，不重复角度筛选。

## 1. 发现角度：内部分析与原始观点扫描

此阶段先用模型作**候选生成与逻辑分析**，不是用模型臆测今日舆论。

具体操作：

1. 遍历作者每个独立判断，寻找可被普通读者辨认的对象：品牌、产品、事件、行业概念、职场行为、制度规则、人物处境。抽象词（“时代”“商业逻辑”“人性”）必须落到具体行为才算切口。
2. 寻找明确可对抗的既有说法：谁声称什么、谁为某件事辩解、什么观念被默认正确；也寻找不需要两派对战的集体厌恶或挫败。
3. 寻找能独立成故事的“一个具体问题”：一次断裂、一次会议、一项KPI、一段甲乙方关系。避免一篇文章批判整个行业却没有一个可理解的动作。
4. 对不同切法各写一句“这篇文章选择从哪里进入，最终想证明什么”。这一步不写标题集，不排文章顺序。
5. 检查是否是同一个切口换了三个形容词。只有对象、要挑战的认识或故事因果不同，才算独立候选。

内部候选数量一般3—5个，公开呈现最多3个。优先保留作者有鲜明原始观点且有事实依据可查的候选。

## 2. 联网查证：争议对象和既有情绪究竟是否存在

**工具规则：模型知识负责提出候选、判断逻辑、发现反例；互联网检索负责验证当下事件、社会情绪、争议对象、流行说法、支持与反对意见。** 有关“近期热议”“大众反感”“行业都在谈”的事实判断，必须联网；绝不能用模型印象、作者单个评论区或助手自己的推测冒充公众反应。

按候选逐一执行以下研究：

**A. 查事实与时间**：搜「候选对象 + 具体事件」「官方声明/原始报告/测试/政策/产品资料」「澄清/后续回应」，优先一手来源并交叉检查媒体报道。区分事件发生日、报道日、作者发文日。涉当前事件先查近期，通常从近7天扩展到30天；长期积怨可延伸更久。时间范围按事件实际调整，不机械限制。

**B. 查真实争点**：搜「对象 + 争议/质疑/反对/支持」「关键辩护理由 + 反驳」「事件 + 评论/行业反馈」。按议题选择公开可访问的平台、专业论坛、媒体评论与相关社区（例如微博、知乎、B站、专业行业论坛等）。寻找具体、可引用的正反立场，避免只搜索吻合作者判断的材料。不要把重复转载、同源宣传当多个独立观察样本。

**C. 查群体情绪先后**：验证情绪是作者发布之前就已存在，还是作者文章引发的二次对抗。记录能找到的评论、公开讨论、报道、时间线；无法查到可代表群体的证据时，只称“检索到某些讨论”，不能声称“广泛愤怒”“全网都在说”。

**D. 查目标读者认知度**：对象对于预期读者是否本来可识别？FDE可以是ToB行业强认知而非大众热词。“认知度高”需有相关讨论或受众基础迹象；没有可靠热度指标则以定性判断表达，不编造搜索量、声量或关注人数。

**E. 主动反证**：搜可能推翻事实或因果解释的材料，包括当事方回应、第三方测试、不同人群经验、替代原因。把“争议的事实”“作者的裁决”“尚未证实的动机”分别标注。

每个角度的研究结论只保留：事件/争议的可查事实、既有情绪的可见证据、对立的关键说法、主要反证、来源及日期、尚不确定之处。若网页无法访问、平台数据不公开或实时检索不可用，明确限制，不将其补成确定结论。

旧文/历史覆盖核查：涉及作者此前是否写过、发表了什么或表达过什么，优先查询 Notion「Blog数据库」，只认 state=Published 且 type=Post，并读取相关正文全文；其他草稿、观点资料按对应数据库获取。不可仅凭记忆断言历史。

## 3. 选择方法：同一 Skill 内的不同叙事入口

这五种是**工作分类**，不是已被科学证明的五大法则。每篇优先选一个主要入口；可有次要元素，但不要为了完备而同时套五个。

- **情绪裁决法**：适用于已有鲜明集体情绪或阵营争议、且作者有可辩护判断的情形。具体操作：确定读者熟悉的争议对象 → 找到争论中要否定的说法或引发共同不满的行为 → 选一个可核实的具体切口 → 用一句硬判断“下判决”。标题可以完整点名，也可以在热点语境和封面能补足对象时省略主语。点击因果假设是：对象识别 → 激活既有态度 → 想确认/反驳裁决 → 点击。无既有情绪、缺乏论据时不强套。
- **认知反转法（路由判断 v0.2）**：**从作者已输出的观点 P 出发，识别其是否迫使目标读者修正某个既有理解 A。** A 可以是主流共识，也可以是目标读者普遍的预期、默认因果解释或对重要性的排序；不要求全国主流，但必须在目标读者中具有真实认知基础。

执行顺序：

1. 扫描作者全部原始观点，找出可能改变读者理解的 P，不要求作者先提供反方，也不先设计一个主流论点供反驳。
2. 逆向识别 P 挑战的是哪一种明确的 A：被普遍接受的结论、预期、因果解释或重要性排序。A 只能作为待验证假设，不能写成“大家都认为”。
3. 按受众和话题联网核验 A 的实际存在及 P 的事实基础，寻找反证。不能因找到一个持有 A 的人就认定 A 是主流，也不能因 P 新奇就假设 P 成立。
4. 判断 P 对 A 的冲击：能否推翻某个前提，改变主要原因、结果预期或判断优先级？A 与 P 即使可以同时成立，若 P 足以迫使读者重新理解 A，仍可能是有效反转；若 P 只是补充一个新事实或另一个平行观点，没有改变理解，则不走认知反转。
5. 点击前检验：目标读者只见标题和封面，能否认出原有理解 A 与新判断 P 之间的落差？P 是否可信到值得求证，而不是明显荒谬？

暂定点击因果假设：既有理解 A → 遇到可信但不符合预期的判断 P → 原有解释变得不足 → 产生求证动机 → 点击。注意这是方法假设，不是点击率的因果证明。

淘汰条件：无法确认目标读者存在 A；P 无法提供可信依据；P 只是并列补充而没有显著修正 A；冲突只有看完正文才出现。若 P 是对公共立场作明确判决，优先考虑裁决法；若吸引力主要来自异常结果的原因未知，考虑解谜法。该方法的叙事模板与标题封面模块还需后续具体设计。

- **异常解谜法**：适用于一个确实发生、单凭现有解释难以理解的结果。操作：确认异常事实 → 找到读者自然会追问的原因 → 验证是否有足够材料解释 → 标题只展示异常和关键疑问，不虚构悬念。
- **利益揭示法**：适用于成本、收益、权责在不同主体间错位。操作：锁定一个具体人的损失/负担 → 找到规则、交易或激励 → 追踪谁承担代价、谁受益及其证据 → 用读者能识别的行为呈现冲突。不得凭不满直接推断恶意动机。
- **荒诞现场法**：适用于一个真实、容易形成画面的行为已经足够反常。操作：还原可核实的具体场景 → 把冲突留在场景本身 → 再解释其背后机制。不要用虚构桥段充当新闻事实。

选择方法的关键不是名词，而是**哪一个能让目标读者只凭可见信息就产生最强的、且没有事实欺骗的点击理由**。

## 4. 角度评估与第一轮交付

只对作者提供的原始观点及已查实的社会语境进行比较，不预先写文章逻辑。每个公开候选用6项简短表达：

- **切口**：具体发生了什么。
- **被激活的旧情绪或旧认知**：来自哪个目标人群；证据不足须说。
- **对抗对象/待解疑点**：挑战哪种说法或利益结构。
- **核心判断**：一句可以论证的裁决，或一件需要解释的异常。
- **点击前理由**：读者只看到标题+封面及其既有语境，为什么在意？
- **事实边界**：最关键的反例或未核实处。

最多提出3个真正不同的叙事角度，**明确推荐1个**，理由优先考虑已有注意力、冲突清晰度、目标受众与证据充足性。没有合适裁决条件时推荐其他方法，而不是勉强制造敌人。用户明确选好角度后立刻进入下一步。

## 5. 选定角度之后，才整理观点、逻辑与大纲

此时回到完整原始观点池，逐条判断：哪些是必须使用的事实、哪些提供关键解释、哪些反驳或限定结论、哪些属于另一个故事应删去或留作新选题。

为该角度形成一条主因果链：“具体处境/事件 → 被挑战的解释 → 关键事实 → 为什么造成这种结果 → 反例与适用边界 → 最终判断”。据此重排素材和设计大纲，不按用户发言先后组织内容。

同时回答原有写作总纲：“文章代表哪一个具体处境中的人、他正经历什么、最后替他说清什么话”。但**不让这三问反过来取代点击前选题决策**。

尚在观点探索时不输出整篇初稿；只有作者要求正文时写正文。

## 6. 标题与封面：同一故事角度的双重表达

- 标题目标：尽可能快地让读者识别对象和矛盾，并提供认同、反驳、意外或好奇的点击理由。裁决式标题可采用事实裁决、行业模式裁决、趋势裁决、群体不满裁决；其他类型允许以异常、反转或成本作为入口。句式不是越极端越好，预测不得写成已发生事实。
- 封面目标：帮助认出对象/发生的事，或以视觉隐喻表达文章核心机制。优先找一件有辨识度的具体物体及一个可被看见的动作，不只是重复标题文字。既可以补足省略的主语，也可以通过既有谚语/象征引发联想。
- 形成2—4组**标题+封面配对创意**，说明每组在点击前传递的同一个角度；避免先列十个标题又找不相关的封面。选择哪一组由作者决定。
- 微信公众号以移动端小缩略图展示，检验主题是否可认出、元素是否过细或过多；特定画风（例如黑白、聚光灯）属于作者近期实验，不得当成因果公式或强制模板。
- 事件正在成为热点时可以使用依赖热点语境的短标题；当事件关注度下降、读者难识别时，标题或封面必须补足对象。

## 7. 发布前只检查“点击前”

让助手暂时当作完全没读过正文的读者，只看到标题与封面（以及真实的发布语境）：

1. 我认得这是在说谁/什么吗？
2. 我看到的是冲突、异常、裁决，还是一个陌生的空泛概念？
3. 为什么我会想“凭什么”“怎么会这样”“终于有人说了”？
4. 标题有没有过度承诺、偷换对象或暗示一个未经证实的事实？
5. 缩略图还能看懂关键物体和动作吗？

不符合则先改切入角度或标题封面，不用增加正文价值来辩护。微信当前缺少作者可执行的正式随机A/B分流，不把A/B测试当成默认步骤。若用户提供真实曝光、打开、推荐来源及展示方式，做观察性复盘；评论量、转发量不是标题点击率。

## 8. 源案例：校准而非套模板

- 《断了就是断了》：尊界踏板断裂已成为当时讨论焦点；标题省略对象、直接作事实裁决；封面是一根**断裂的巧克力棒**，靠“断了”的动作与热点语境发生联想。评论区的激烈争论不直接证明标题点击率。
- 《中国式FDE注定失败》：FDE是行业目标受众熟悉的讨论对象，“中国式”“注定失败”下趋势/模式裁决；封面是**从天而降的巨锤砸向一大排钉子**，指向“手里拿着锤子，看什么都是钉子”，隐喻预先有AI方案、然后为方案找问题，不是简单画一个“失败”。
- 《开会浪费生命》：对形式主义会议、职场政治表演的集体厌恶提供裁决切口，不必预先存在势均力敌的两派；文章论证需聚焦无效会议，不能把所有会议都未经限定地推为无用。

样本展示的是可供验证的创作因果假设，不能从三篇反推出普遍成立的点击率规律。

## 9. 输出契约、失败回退与存储

**探索观点阶段（Skill 外）**：作者自由讨论时不调用本 Skill；仅回应当下的观点问题，不擅自定主题。

**要求找角度阶段**：先搜证据，再给不超过3个不同角度及一个优先建议；不抢先排逻辑和写大纲；附关键事实来源。不得用名词解释替代实质筛选。

**确认角度后**：只输出该角度对应的观点取舍、因果链和文章大纲。

**要标题封面时**：输出联动创意方案；需要正式生成图片时才执行图片制作。

**没有可验证的既有情绪**：说明证据不足，尝试反转、解谜、利益或现场法，不硬凑裁决。

**作者已提供足够事实**：保留作者陈述作为输入，不为了展示严谨而重复质疑；需要对外发布的重要客观事实才做必要的外部核验，并明确区分作者输入和检索证据。

**资料管理**：本 Skill 保持为一份方法文档，统一迭代修订；单篇文章和候选观点另存到用户指定的文章或选题数据库，不在每个创作任务中复制一份方法文档。
