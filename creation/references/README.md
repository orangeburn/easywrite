# Creation references 使用约定

本目录存放**辅助资料**，不承担 Creation 的入口路由，也不直接规定文章怎么写。执行规则以 [Creation 入口](../WORKFLOW.md) 和对应的 [methods](../methods/) 为准。

## 目录内容与触发条件

| 文件 | 内容 | 何时读取 | 不适用场景 |
| --- | --- | --- | --- |
| [reversal-evidence.md](./reversal-evidence.md) | 认知反转相关研究、原始来源与外推限制 | 解释或修订认知反转法；**检查输出**中关于意外、好奇心、认知更新、标题信息量或点击效果的推论是否越界时 | 无相关理论问题的常规生成；以文献代替具体选题的事实或受众认知核验 |
| [mystery-evidence.md](./mystery-evidence.md) | 解释寻求、惊讶、信息缺口和标题具体程度的研究及适用限制 | 讨论/修订异常解谜方法，或检查输出是否把惊讶直接等同于点击、把解释不足写成确定因果时 | 无相关理论疑点的普通角度生成；替代本次事件的事实与因果核验 |
| [interest-evidence.md](./interest-evidence.md) | 利益分配、激励、经济负担与信息回避的研究边界 | 方法讨论、修订；**结果检查**涉及「受益等于意图」「成本必然零和」「利益一定引发点击」等推断时 | 平常切换叙事视角时机械加载；以理论资料决定话题是否值得写或代替事实查证 |
| [verdict-evidence.md](./verdict-evidence.md) | 情绪与负面标题的点击研究及外推边界 | 解释／修订裁决法，或检查「激烈判决／负面表达必然有效」时 | 取代某个读者群体的真实情绪证据 |

| [notion-original.md](./notion-original.md) | 创建 GitHub Skill 时的 Notion 原文快照 | 追溯历史版本、核对迁移内容时 | 当作最新指令，覆盖 `WORKFLOW.md` 或 `methods/` |

## 读取原则

1. **按问题而非固定阶段决定是否读取。** 普通创作先读入口、适用方法和本次选题的有效来源；如果在输出检查中发现需要核实的研究推论、历史案例或方法边界，也要读取**相关** Reference。
2. **就事读取，不做全目录预加载。** 方法讨论、方法修订、结果检查都可以触发相应 Reference；检查没有涉及该资料所能回答的问题时，不必加载。其他方法无关的资料和历史快照不读取。
3. **参考资料不替代方法规则。** 文献可以支持或反驳一个机制，不能直接证明我们定义的整个方法有效；研究和方法矛盾时应指出并修订方法，而不是假装研究已经验证了它。
4. **参考资料不替代事件核查。** 真实人物、品牌、行业共识、社会情绪、成本数据和新闻事件都要为该选题另外查证；老论文或历史案例不能证明当下读者一定存在某种态度。
5. **不默认向作者展示资料。** 创作输出只保留与当前任务有关的事实、候选和不确定性；用户问依据时才解释相关文献。

未来可以增设案例、数据和视觉参考文件，但必须写明用途、触发条件和失效边界。
